# 总体路线图

目标：从多来源文本重建一个有原文依据、可纠正、可评估的人物模型，并逐步支持角色对话。

## 阶段与交付标准

| 阶段 | 要完成的工作 | 交付物 | 完成标准 | 依赖／状态 |
| --- | --- | --- | --- | --- |
| M0 项目与问题定义 | 仓库、目录、范围、研究问题、文献地图 | README、研究计划、任务板 | 新参与者能找到计划和当前任务；明确尚未实现的内容 | 正在收尾；文献地图已建立 |
| M1 研究与方案 | 精读核心论文，比较表示、证据和评估方法；准备 Nicole 讨论材料 | 概念词典、字段依据表、反例、1–2 页技术概念说明 | 每个候选设计都有出处或明确的工程假设；关键异议与未知项可检查 | 当前重点；聚焦Schema理论和方法依据，不以P27为起点 |
| M2 Schema 与人工小样本 | 定义来源、人物、证据、主张、人格与冲突；手工标注样例 | Schema v0.1、合法／非法示例、标注指南、小型样例集 | 原文可定位；能表达未知与冲突；区分特质和状态；样例可通过约束检查 | M1 的首批综合结论 |
| M3 文本抽取原型 | TXT／Markdown 后扩展 DOCX；分段、归属、抽取、验证、整合、导出 | 可重复运行的 Python 流水线与运行说明 | 一条命令处理公开样例；每条主张有证据或明确不支持；运行有模型／提示词／成本记录 | M2 |
| M4 审核与质量验证 | 简单档案审核界面、人工对照、消融、错误分析 | 审核原型、评估报告、Schema v0.2 | 报告支持率与遗漏、冲突和归属错误；修正可追溯；保留失败案例 | M3，可与原型迭代 |
| M5 文字角色对话 | 经审核的设定、故事知识与互动记忆分开；匿名行为测试 | 最小文字聊天 Demo | 能检索设定与证据；不把聊天新信息静默覆盖原著；多轮检查有记录 | M4 基线明确 |
| M6 后续产品化 | 按验证结果选择视频转文本、语音、账号、权限、部署或迁移 | 独立范围说明和验收方案 | 有用户任务与收益证据再立项 | 后续，未开始 |

M1 的桌面研究和专家反馈先服务设计；不要求 coffee chat 成功约到才能做 M2 的人工建模。实际约谈由用户决定，本计划不发送邀请。

## 系统工作包

| 工作包 | 必须处理的问题 | 主要位置 |
| --- | --- | --- |
| 来源与导入 | 文件类型、来源类别、作品版本、定位和分段 | `data/`、`src/echoloom/` |
| 人物归属 | 别名、说话者、指代与不同版本 | `docs/design/`、`schemas/` |
| 证据与主张 | 原文片段、观察／自述／解释、支持与反证 | `schemas/`、`docs/evaluation/` |
| 证据整合 | 重复、冲突、时间变化、来源优先级 | `docs/design/`、`experiments/` |
| 人格建模 | 特质、目标、价值观、情境行为、语言风格 | `literature/`、`schemas/` |
| 用户审核 | 确认、拒绝、修改、版本和可追溯性 | `docs/design/`、`src/echoloom/` |
| 评估 | 原文忠实性、覆盖、匿名情境行为、审核成本 | `docs/evaluation/`、`tests/` |
| 后续对话 | 故事事实、人格和互动记忆的边界 | M5 后进入实现 |

完成一个阶段后，在任务板更新状态，并用决策记录说明范围或方法的变化。上述阶段不是固定工期承诺。
