# EchoLoom — Scene Rehearsal Studio

2026-11-06 · 根据[用户提供的 PRD v1.0](scene-rehearsal-prd.md)重新设计。用户最新补充：**默认英文**，生成使用场景保存的语言；可选中文。

## 新的产品方向

**Let your characters play it out.** 两个人物、一个局面，即可排演。创作者能介入反应、亲自演一人、试不同走向，最后确认值得保留的本场结果，再接下一场。

默认入口现在是 `/rehearsal`；网站根地址也进入该入口。采用星夜剧场视觉：深靛背景、紫色暮光、香槟金按钮、衬线标题、角色卡和纯净阅读舞台。全局导航只在列表显示；创建和舞台使用返回导航。角色库、创建、档案调整与头像版本现在也在同一移动端。`/characters` 与 `/characters/new` 自动进入新的移动端角色页面；旧伴聊列表保留在 `/companion`，旧 Creator `/creator` 与已有聊天链接继续可用，旧作品不自动转成排练，也不清空。

## 怎样测试

无需密钥：选择列表下方 **The station reunion · Demo**。预置 Lin / Xu 和车站局面，始终显示 DEMO；可演出、接管、加入事件、走向选择、版本切换、保存、导出和下一场。任意自由导演要求超出演示范围会提示需要 Live AI，不用通用套话冒充真实推演。示例结尾会停止，不无限重复台词。

自定义排练：

1. **Rehearse a scene → Choose your cast**。选择 A/B 两位人物；**Create** 进入同一移动端的角色创建页。输入一段描述，点一次 **Create character**，自动生成档案并生成、选中第一张头像。之后可以 **Edit character**、**Refine with AI**、**Edit portrait**，再 **Use in this scene**，原选角／开场草稿保留。底部 **Characters** 也进入同一角色库，可从人物详情 **Rehearse with…**，自动带入角色 A。档案、头像、历史与调整都不跳旧网页。

   图像失败会保留角色，**Retry portrait** 只重试图像；请求中断使用原请求 ID 查询／恢复，不重复生成档案。档案先生成、头像随后自动生成，界面显示两步状态。新建人物和头像使用服务端真实模型，正常产生 API 费用；头像缺失时仍保留占位形象。
2. **Next: set the scene**。只填写局面即可开始；目标、小说／剧本、关系、地点、时间、各自知识与规则可选。输入本机立即保存，设置页面约 800ms 防抖同步。**Review setup** 原样整理明确输入，不调用模型、不添加猜测；不会伪造 AI 提取结果。
3. **Start rehearsal**。新内容默认只显示第一句；点击 **Next line** 再显示下一句，不自动展开整段，也不自动替用户继续演出。全部读完后，按钮才变为 **Continue** 生成下一片段。旁白、动作和对白均按句推进，接管角色时也可逐句阅读 AI 回复。每句之后都能 **Intervene**、编辑或探索其他走向。**Next line 只读取已生成内容，不调用模型**；阅读位置按版本保存，刷新恢复。
4. **Intervene** 可给一次性／持续指令、加入一次事件、接管一人或调整设定。接管后的输入原样锁定保存，AI 只演另一人和环境；失败可 **Retry response**，不重复插入你的台词。**Hand back role** 不会自动生成。
5. 段落右侧 **···** 可编辑、换反应、从此重演、探索走向或记录人物反应反馈。文字润色新建版本并保留后文、提示复核状态；剧情修改锁定作者文字并排演新后续。原路线一直保留。
6. **Other directions** 先生成两张候选卡，不改正文或记忆；选择后才建立实验版本。顶部 Version 可切换、命名、删除允许删除的版本，切换不生成内容。
7. **More → End scene & review**。查看完整正文、基于正文的回顾、人物变化和线索。摘要失败仍可保存和导出。**Save this scene** 明确认可当前版本；自动保存草稿不等于认可结果。
8. **Export scene** 支持复制、TXT、Markdown；可选择标题和角色名，不包含隐藏笔记、内部指令、其他版本。UTF-8/BOM 和过滤文件名用于 Windows 文本兼容。
9. **Rehearse the next scene** 固定引用本场认可结果、两人物快照及其状态。后续改选上一场结果会提示旧来源仍被保留，不自动重写下一场。存在后续依赖时禁止删除来源场景／版本。

## 任务、暂停和恢复

每个操作带唯一 ID 和预期 revision；同一场只运行一个生成任务。任务持久化为 queued/running/completed/cancelled/failed，客户端通过带序号、任务 ID、版本 ID、块 ID 的事件轮询读取。切版本可查看历史，任务仍写入原目标，迟到结果不会进入别的版本。

**当前模型适配器先取得并校验一整个结构化片段，再逐完整块提交并发送块事件，不做 token 级实时流；客户端只按已保存的逐句阅读游标显示，不随轮询把整段展开。** 因而模型返回之前暂停，会保留原节点；提交阶段暂停只保留已提交块。不会显示假进度或保存半句。前端断开后可重新查询实际任务；暂停不保证取消供应商侧的计费请求。

读到中途介入、接管或改写，会从已读前缀另开版本，原版本完整保留。未读对白和未读块带来的知识变化不进入新方向的模型上下文；走向卡也只根据已读内容生成。结束本场与结果确认使用已读内容，舞台导出同样只导出当前已读前缀。旧版本没有阅读游标时兼容为已读全部，后续新生成片段仍只展示第一句。游标保存在现有 JSON 文档中，不需要新增 SQL 迁移。

服务端任务初始预算 60 秒；15 秒前端显示等待说明。超时／重启保留已提交正文，显式重试，不自动再发付费生成。失败重试用新任务 ID，并关联原任务，避免旧 worker 写进新任务；用户输入不会重复。草稿版本冲突需要加载服务器稿或将本机设定另存一场，不静默覆盖。

## 真实能力与边界

- 自定义排练、两走向和正文回顾使用现有服务端文本模型配置。根据用户后续要求，UI 的角色创建统一改为一键档案＋头像，复用已有 `/api/creator/characters` 幂等创建链路；头像编辑／候选选择、档案字段修改／AI 差异预览确认、档案历史恢复都使用同一移动端。底层作者手填 API 仍兼容，但不再作为主创建入口。
- 规则冲突通过结构化生成的 conflict 字段阻止演出并显示具体规则；格式、说话者、知情 ID、状态来源、锁定文字和分支路径有程序校验。模型格式／角色错误最多两次修复，网络错误不因此额外重试。
- 每个节点保存分支状态：世界事实、知情信息、误解、目标、单向关系、线索；每条生成状态记录来源。**知识与硬规则的语义可靠性仍须人工评审**，不能把结构检查当成保证。当前没有独立的语义审查模型或自动“改字是否改事实”判定器；文字编辑由作者选择类型并复核。
- 作者反馈记录在本场，不自动改写原始人物或私人聊天。人物母版修改／删除不影响已保存的文本快照，缺失图片显示首字。
- 本地内容缓存和草稿不上传通用分析平台；服务器按账号检查所有场景、版本、任务和导出。用户退出／换账号后不会用另一个账号的缓存替代权限错误。
- 使用事件基于服务端操作记录，`GET /api/rehearsal/metrics` 只返回当前账号按场景去重的计数，不包含正文、秘密或提示词，不向外部分析系统上传。
- 当前每场限 1000 节点、100 版本、约 4 MiB；长期写作应保存并接下一场。状态压缩有预算，不承诺无限记忆。尚无七日留存看板、跨设备云同步、原生 App 或语音演出。当前为单进程本地服务；缓存用于已打开页面的断网恢复，不是支持离线首次启动的 PWA。
