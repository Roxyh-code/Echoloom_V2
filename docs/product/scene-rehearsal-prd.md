## 1. 产品目标与定位

**让你的角色先把故事演出来。**用户选择或快速创建两位角色，描述一个局面，即可观看符合人物设定的分段演出；随时修改对白、下导演指令、加入事件或接管一个角色；从关键位置尝试不同走向，最终保存认可的版本并接着排下一场。

主要用户是已有角色、人物关系或片段灵感，但卡在具体场景、人物反应或对白上的小说、剧本及互动叙事创作者。第一版聚焦两角色创作，不同时承接商业谈判演练。

用户应能回答三个问题：人物在这个局面里会怎么做？改变一个条件后会发生什么？哪个版本值得成为我的故事？

### 1.1 体验原则

- 两个角色加一句局面即可开始；补充设定渐进展开。
- 保持人物声音、行动动机及知识边界，禁止无依据的全知反应。
- 每次演出短片段，保留创作者介入空间。
- 用户改过的内容是明确输入，重演不得擅自覆盖。
- 实验版本与保存结果分开；所有改动可追溯。
- 用直接的创作语言操作，不把搜索算法、参数权重或 Agent 日志展示给用户。

### 1.2 第一版范围

| 优先级 | 功能 |
|---|---|
| P0，完整上线闭环 | 排戏列表；选择两角色；快速创建；开场设置；分段演出；暂停；导演指令；加入事件；接管角色；段落编辑与重演；版本切换；自动保存；本场结果确认；复制和 Markdown/TXT 导出；下一场 |
| P1，首版之后 | 更丰富的设定导入、句子收藏、跨场故事地图、角色一致性分析、语音演出、配乐 |
| 明确不包含 | 超过两位可发言主角色、MCTS、大规模路径搜索、数值心理控制台、多人实时协作、公共角色市场、完整小说一键生成、PDF/Final Draft 专业排版、自动回写原角色记忆 |

## 2. 与现有 Echoloom 的集成

在现有底部导航增加或复用「创作」入口，默认落地「我的排戏」。不得未经审查重做现有导航结构：若已有创建中心，优先将排戏纳入该中心；移动端底部主要入口总数不超过五个。

本规格不依赖现有路由、数据库或组件名称。开发前检查仓库，再映射到现有登录、角色列表、角色创建和存储能力；以下路由与字段是建议契约。

| 现有能力 | 集成方式 |
|---|---|
| 我的角色 | 引用当前用户可访问、可用于创作的角色；保留来源 ID |
| 角色创建 | 复用完整创建能力；增加排戏内快速创建入口 |
| 角色聊天／一起做什么 | 保留原有陪伴体验；排戏是作者控制两角色的独立创作空间 |
| 身份和会话 | 沿用现有账户；所有排戏与导出按用户授权访问 |
| 头像生成 | 可复用，但不是开场前置条件；默认头像可立即使用 |

首次进入排戏时建立角色设定快照。现有私人聊天、陪伴记忆默认不注入排戏。排戏产生的故事记忆只属于本项目，第一版不支持写回原角色。原角色后来修改时，本场不自动变化。

## 3. UI 主题：星夜剧场

参考用户提供的两张手机界面：深靛色星空、紫色暮光、香槟金按钮与细描边、衬线标题、精致插画人物卡片。继承氛围与材质，使用通用创作语言，不沿用参考里的命运任务、倒计时或恋爱限定设定。

### 3.1 视觉分层

- 列表和创建页：顶部局部紫色暮光与稀疏星点，向下渐变深靛。
- 舞台：深色纯净阅读面；背景只在顶栏和页边保留极弱星轨。
- 卡片：不透明度足够的深蓝紫面板、1px 暖灰金边、16px 圆角。
- 主按钮：柔和香槟金渐变、深褐文字、48–52px 高度；每个视图只突出一个主要动作。
- 图标：统一细线风格，少量四角星作为点缀；主要操作必须带文字。
- 不将参考截图外部的米白幻灯片和粉色文案复制进 App。
- 不使用参考截图的播放覆盖层、进度条或手机外框，它们不属于产品 UI。

| Token | 值 | 使用位置 |
|---|---|---|
| background/base | #10121F | 主阅读背景 |
| background/top | #282741 | 顶部星空底色 |
| surface/card | #1B2033 | 人物、场景卡片 |
| surface/elevated | #252A40 | 抽屉与弹层 |
| accent/gold | #D8C08D | 主按钮、当前选择 |
| accent/gold-deep | #AC9160 | 渐变与装饰 |
| text/primary | #F4F0E7 | 正文、标题 |

正文与背景对比度至少 4.5:1，大字至少 3:1；上述值是候选，不视为自动通过。状态除颜色外同时使用文字或图标。

### 3.3 字体与移动规范

英文标题可用项目已有衬线字体；中文标题用具备授权的宋体类字体或系统衬线回退。正文使用系统无衬线，避免整屏装饰字体。标题 24–28px，正文 16–18px、行高 1.65，辅助信息不低于 12px；阅读字号可调整。

以 390px 宽为设计基准，支持 320–430px；更宽设备内容居中。页面左右内边距 20px，小屏 16px，组件间隔采用 8px 基准。交互热区至少 44×44px。使用系统安全区，底部操作栏不得压住正文。抽屉通常为屏高的 60%–90%，长表单可扩展为全屏。

键盘弹出时底部表单按钮随可视区域上移，舞台创作操作栏被角色输入栏替代；避免出现两组重叠的固定底栏。支持系统返回、读屏、减少动态效果与文字放大。星点不持续闪烁，转场 160–240ms；减少动态效果时取消装饰动画。

## 5. 用户动线

### 5.1 首次创作

进入创作 → 新建排戏 → 选角色 A、B → 下一步 → 输入局面 → 开始排戏 → 首段完成 → 继续／介入／其他走向 → 结束本场 → 选择认可版本 → 保存本场。

首次只在舞台首段完成后显示一次轻提示：「随时暂停，改变一句话或亲自演一个角色。」不设置多页教学。

### 5.2 版本探索

舞台选择段落／当前节点 → 其他走向或编辑 → 创建实验版本 → 演出 → 切换查看原版本 → 回顾页设为本场结果。版本切换不触发重新生成。

### 5.3 连续场景

已保存回顾 → 接着排下一场 → 带入所选结果的角色状态和已发生事实 → 填新局面 → 新场景排练。下一场与上一场存在明确来源关系。

## 6. P01 我的排戏

### 布局

顶部小型星徽与「创作」，主标题「让角色，把故事演出来」。右上角更多设置。标题下香槟金「＋ 排一场戏」。下方筛选「全部／排练中／已保存」，以及按标题搜索入口。第一版默认最近编辑优先。

场景卡片采用参考图的人物列表质感：双头像、标题、两行以内局面、状态、更新时间。整卡可点击；右侧更多包含重命名、删除。草稿显示「继续设置」，已保存显示「查看本场」，排练中显示「继续排练」。

空状态：「让两个角色相遇，看看故事会往哪里走。」主按钮「排第一场戏」。

删除使用明确确认，说明会删除本场全部版本；若有后续场景，P0 阻止删除并列出后续场景入口，避免断开来源。可先删除后续场景，再删除本场。删除不影响原始角色。

## 7. P02 选择两位角色

顶部步骤提示「1/2 · 选择角色」，标题「这场戏，谁来演？」。上部固定两个等宽角色位，显示已选头像、名字和移除按钮；点击空位指定当前填充位置。下面「我的角色」含搜索和「＋ 创建角色」，角色按最近使用排序。

人物卡片包含 56px 头像、名字、一行性格描述；点击选中，显示金色描边和 A/B 标签。点击详情图标展开人物信息，不改变选中状态。未指定位置时先填 A 再填 B。已选两人后点击第三人，提示选择替换 A 或 B。

恰好两位不同角色才能继续；第一版不支持同一角色复制后与自己对戏。底部按钮「下一步：设置开场」。返回列表保留草稿。角色加载失败时保留已有选择，允许重试或快速创建。

### S01 快速创建

必填：名字 1–30 字；人物描述 10–1500 字。可选头像，默认头像立即可用。按钮「创建并加入本场」。成功后存入我的角色并填入当前角色位，失败保留全部输入，防止重复提交。AI 可辅助整理人物描述，但必须先显示预览，由用户确认；不自动添加重大身世或关系。

### S02 角色详情

显示原始人物描述、来源以及本场将使用独立设定的说明。底部按钮「加入本场」或「已选择」。角色头像失败时使用首字头像，不阻塞选择。

## 8. P03 开场设置

顶部「2/2 · 设置开场」与两个头像。主输入「把他们放进什么局面？」必填 10–2000 字，4–6 行起始高度，自适应至合理上限。可选「你想看什么发生？」最多 500 字。默认表现形式「小说场景」，可选「剧本对白」。

示例占位：多年未见的两人在车站重逢。林知道许曾经出卖自己，但许不知道秘密已经暴露。

可选目标：表面温柔，但最后两人的关系出现裂痕。

下方收起区「补充本场设定（可选）」：两人关系、场景地点／时间、A 知道什么、B 知道什么、必须遵守的规则。每字段最多 1000 字，规则最多 10 条，每条 200 字。信息不完整仍可开场。

可点击「整理设定」提取已输入内容。明确提取的事实与 AI 补充的建议分别标记；建议未被用户接受前不进入硬规则。提取不得改变原始输入，不重复消耗生成请求。修改来源文字后，旧提取结果标记待复核。

底部「开始排戏」，提交时先持久化草稿与角色快照，再创建首版本并生成首段；点击后禁用重复提交。标题可由局面生成，失败回退「未命名场景」，可随时改名。正文不等待标题生成。

## 9. P04 排练舞台

### 9.1 布局

顶栏：返回、场景标题、版本名（可点击）、更多。标题下「人物与设定」小型入口。正文全宽阅读，不做两侧聊天气泡：旁白为段落，发言显示小头像＋名字＋对白，动作与对白分块。颜色不可成为区分角色的唯一方式。

每个片段起始处可折叠显示「片段 01」；人物不需要每句重复完整头像。用户编辑文字带轻量「已编辑」标识，可通过段落菜单查看版本来源。生成中显示「正在排演…」，不显示虚构的进度百分比。

底部固定操作：左「我来介入」，中香槟金「继续演」，右「其他走向」。更多包含「结束本场」「场景设置」「复制当前版本」。持续提供保存状态：保存中／已保存／未同步。

### 9.2 演出节奏

每次请求生成一个片段，建议 3–6 次对白和必要动作，总长约 200–500 中文字，属于可调整的默认预算，不是硬性文风要求。每次在自然反应点或决定点停止，不强行每段制造悬念。角色也允许沉默、妥协和暂时离场。

首段先快速建立场景并进入互动，避免重复输出人物卡。生成默认只续写当前位置之后，不改历史。到达合适收尾时给出「这一场可以在这里结束」建议，用户仍可继续。

### 9.3 暂停与部分结果

生成时中间按钮变为「暂停」，其他会改变剧情的操作暂不可用。服务器以语义块（完整对白／动作段）提交，前端可在当前块内流式显示。暂停时提交已完成块，未完成块不进入正式版本；用户看到提示「已停在上一段完整内容」。后续继续基于已提交内容。

如果尚无完整块，暂停返回原节点。重复暂停不重复提交。取消后迟到的流事件不得追加到当前版本。用户离开页面后本次请求状态由服务器记录，返回读取实际结果，不重复生成。

### 9.4 滚动

用户停在底部时跟随新内容；向上阅读后停止自动滚动，显示「查看新内容」。片段完成保持当前位置。底部保留额外安全留白，末段可完整滚出工具栏。

## 10. S04 导演介入

入口抽屉标题「你想怎样改变这一场？」；四个操作分别进入输入状态。

| 操作 | 输入和行为 | 确认按钮 |
|---|---|---|
| 给一句导演指令 | 如“让许挽留，但不要直接说舍不得”；默认只作用下一片段 | 按这个方向继续 |
| 我来演一个角色 | 选择 A/B，进入接管模式 | 开始对戏 |
| 加入一个事件 | 如“列车广播响起”；事件成为接下来实际发生的内容 | 加入并继续 |
| 调整本场设定 | 修改目标、关系、知识或规则；说明生效点 | 应用并重演／从这里继续 |

指令最多 1000 字，空白不可提交。指令与人物硬规则冲突时，不静默忽略：显示具体冲突，由用户修改指令或修改规则。主观人格倾向属于软设定，不使用绝对违规告警；系统可提示需要铺垫。

导演指令默认一次性；可选「持续到本场结束」。有效指令在人物与设定抽屉可查看和停用。停用只影响未来，重演历史需新建版本。事件只提交一次；重新请求使用同一操作 ID 防止重复发生。

### 10.1 接管模式

底部工具栏替换为「你正在扮演：林」状态条、文本框及「发送」。输入可以是台词或动作，支持明确的动作标记。AI 不代写被接管角色的新台词、决定或内心；只演另一角色和必要环境，不将用户未写的行动补成既定事实。

提交后用户输入作为锁定内容保存，AI 生成对应回复。失败时用户输入仍保留；重试只重试对方回复。提供「交还角色」，返回导演模式，不自动触发继续生成。允许用户切换接管对象，切换前保留未发送草稿。第一版每次只能接管一位。

## 11. S05 编辑与局部重演

点按段落打开菜单：编辑这段／换一种反应／从这里重演。支持设备文本选择复制；长按优先遵循系统选择行为。

编辑分为两种：仅改文字（修辞、错字，不改变事件）和改变剧情（台词含义、动作、信息变化）。默认让用户确认类型；系统可提示判断但不得代替用户确认。

- 仅改文字：创建修订版本，保留后文并重新检查状态；如发现可能的事实影响，提示切换剧情修改。
- 改变剧情：从所选段落之前的状态新建版本，将用户编辑段作为锁定段，然后生成后续。原后文保存在旧版本。
- 换一种反应：保留该段之前内容，说明希望改变什么，重生成该段及之后。
- 从这里重演：清楚显示重演从该段开始；所选段及后文不会被复制到新版本。

所有操作都保留旧版本。用户编辑内容只有再次明确选中修改，才能被改写。点击生成前提示「将创建新版本，原版本保留」，不反复弹出强确认。

## 12. S06 其他走向与 S07 版本管理

「其他走向」基于当前已完成节点，生成两张不同走向卡及「我有别的想法」。每张卡包含标题、关键选择、可能带来的关系或信息变化；每卡约 60–100 字。点击卡片后才生成完整片段。卡片本身不写入角色记忆。

差异必须来自决定、信息披露、行动或关系方向，不能仅改写措辞。不展示最优分数、现实概率或“必然发生”。自定义输入与导演指令同样检查硬规则。

版本显示「版本 1」「版本 2」及一句来源说明，例如「从片段 02 起，许主动坦白」。版本列表标记当前查看、本场结果、生成中／失败。可重命名，可删除非当前结果且无后续场景引用的版本；否则要求先更换结果或删除依赖。切换版本保留阅读位置。

在新版本生成期间可查看历史版本，但在同一场景中只允许一个生成任务；切换不会把新文本写入正在查看的旧版本。返回生成版本时显示实际进度。

## 13. P05 场景回顾与结果确认

舞台点击「结束本场」进入回顾，先展示当前版本；只有用户确认才将其标为本场结果。回顾包含完整正文（默认可折叠摘要）、剧情摘要、人物变化与未解决线索。摘要由已完成正文生成，不可额外发明事件；失败时仍可保存和导出正文。

底部主要按钮「保存本场」。保存成功显示「已保存为本场结果」，操作变为「接着排下一场」，并提供「继续修改」「导出」。普通退出已自动保存为草稿，不等于认可该版本。

如果用户改选本场结果，已建立的后续场景仍引用原结果快照，并标记「上一场结果已更新，当前仍基于旧版本」。P0 不自动重写后续场景；用户可从新结果另开下一场。

### 导出

支持复制正文、下载 TXT、下载 Markdown。选项：包含场景标题／角色名；默认不包含内部导演指令、隐藏设定和系统检查日志。小说格式保留段落，剧本格式按角色名与动作排版。中文使用 UTF-8，文件名过滤非法字符；导出失败可重试或复制。

### 接着排下一场

预填两角色及上一场认可版本的状态；显示「接续：车站重逢 · 版本 2」。用户输入新局面，仍可调整本场条件，但须区分既有事实与新发生变化。下一场换角色属于后续扩展，P0 沿用原两人。

## 14. 角色状态与叙事规则

每条分支分别维护：世界事实、事件顺序、角色 A/B 的已知事实、误解、当前目标、单向关系、未解决线索、有效规则。作者私有信息与角色可知信息必须分开。

例如作者知道“许出卖了林”；林已确认；许误以为林不知情。生成许的行为时可使用其自己的事实和误解，不能因作者给出了秘密，就让许知道林已经发现。叙述者可按表现形式叙述，但不能把作者笔记直接变成对白。

硬规则包括作者明确锁定的事实、不能提前揭露的信息、世界限制；软设定包括性格、原则、关系倾向。软设定变化需有触发事件和过程，不能把所有人物原则都当永不可突破的机器规则。

用户指定“必须争吵”与人物倾向不符时，可先呈现铺垫，或提示冲突；不通过直接改写性格来达成目标。对无冲突要求的场景，不默认强制对抗。

## 15. 生成链路与服务契约

以下是实现建议，不指定模型供应商或框架。开发需复用现有可用服务并保持替换能力。

1. 验证所有权、当前版本与输入长度。
2. 获取分支节点快照、锁定文本、有效指令和有限的相关历史。
3. 确定本段目标、两角色意图和可见信息。
4. 生成带角色 ID 的结构化动作／对白块。
5. 检查格式、知识边界、硬规则、锁定文本和重复内容。
6. 必要时限次修复；P0 最多两次修复，仍失败则返回可理解的错误，不无限重试。
7. 持久化文本块与状态变更，向前端发送完成事件。

检查不宣称百分之百避免人物失真。错误可由用户通过“人物反应不对”反馈，记录具体段落及纠正内容，优先以用户确认的设定修正。

### 15.1 概念接口

| 接口行为 | 主要输入 | 主要输出 |
|---|---|---|
| 新建／更新草稿 | 两角色、局面、可选设定、revision | scene_id、revision |
| 开始／继续 | scene_id、version_id、base_node_id、operation_id | job_id、流事件 |
| 暂停 | job_id、operation_id | 已提交节点、job 状态 |
| 应用介入 | 节点、类型、内容、持续范围 | 新节点或新版本、job_id |
| 获取走向 | 节点、有效设定 | 两张候选卡及候选 ID |
| 建立分支 | 来源节点、候选 ID／自定义输入 | version_id |
| 保存本场结果 | version_id、expected_revision | result_version_id、revision |
| 接续下一场 | source_scene_id、source_version_id、新局面 | 新 scene_id |
| 导出 | scene_id、version_id、格式、选项 | 文件／文本 |

使用 operation_id 幂等；更新带 expected_revision，冲突时拉取当前状态并提示，不静默覆盖。流事件至少包含 job_id、version_id、sequence、block_id 与事件类型；客户端按序去重。模型调用凭据只保留在服务端。

## 16. 数据模型与持久化

| 实体 | 关键字段 |
|---|---|
| Scene | id、owner_id、title、premise、creative_goal、format、status、result_version_id、source_scene_id、source_version_id、revision、timestamps |
| CastSnapshot | scene_id、role_slot、source_character_id、name、avatar_ref、profile、snapshot_revision |
| SceneVersion | id、scene_id、parent_version_id、fork_node_id、label、change_summary、status |
| StoryNode | id、version_id、parent_node_id、ordered_blocks、state_snapshot_id、locked_blocks、created_by |
| StoryBlock | id、type（narration/dialogue/action）、character_id、text、user_edited、source_operation_id |
| StateSnapshot | world_facts、knowledge_by_character、beliefs、goals、directed_relationships、open_threads、active_constraints |
| Intervention | id、version_id、node_id、type、content、scope、active、operation_id |
| GenerationJob | id、owner_id、scene_id、version_id、base_node_id、status、last_sequence、error_code、operation_id |

父节点可共享不可变历史，变更采用新节点或新版本；不得用一个全局记忆数组服务全部分支。摘要只是上下文压缩，不能替代完整原文；关键事实需可追溯到来源节点。若摘要与原文冲突，以用户锁定设定及对应分支原文为依据处理。

表单修改采用本地立即保存＋服务端防抖同步，建议 800ms；生成的每个完整块由服务端提交。离线时可编辑本地草稿，显示未同步，不能发起生成。恢复联网先处理 revision 冲突再继续。

## 17. 状态、异常与恢复

| 情况 | 用户体验与系统规则 |
|---|---|
| 草稿输入不完整 | 保留输入，字段就近提示，定位首个错误 |
| 生成耗时 | 展示真实状态；15 秒给出等待说明；初始服务端超时预算 60 秒，可按供应商实测调整 |
| 生成超时／断流 | 保留已提交完整块，读取 job 确认完成与否后重连或重试，禁止盲目重复生成 |
| 模型格式错误 | 服务端限次修复，失败给出“这一段没有完成，请重试” |
| 硬规则冲突 | 指明冲突规则，允许修改要求；不展示原始 prompt 或堆栈 |
| 知识检查失败 | 尝试修复，失败停止提交违规块，保留此前内容 |
| 切后台／关闭页面 | 返回读取服务器状态和已提交文本，恢复阅读位置 |
| 无网络 | 阅读已缓存内容；编辑显示未同步；生成按钮说明需联网 |
| 保存失败 | 持续保留本地草稿，明确“尚未同步”，允许重试 |
| 原角色被删除 | 已有快照仍可排戏；未建快照的选择页要求替换角色 |
| 图片失败 | 默认头像／渐变替代，内容操作不受影响 |
| 内容无法生成 | 简短说明并允许修改局面；已有内容保持可访问 |
| 两设备冲突 | 提示有较新版本，允许另存当前修改，不能直接覆盖 |

场景状态：draft → rehearsing → saved。进入 saved 后继续创作产生新的编辑版本；既有结果仍有效，直到用户明确更新。生成任务状态：queued／running／stopping／completed／cancelled／failed。任务状态与场景状态分别维护。

## 18. 性能、隐私与可访问性

性能目标属于待实测的上线目标：列表缓存后可立即呈现；正常网络下首个有意义文本块 p95 ≤10 秒，单个片段完成 p95 ≤30 秒。超过预算通过任务状态恢复，而不是依赖前端常驻连接。长场景按片段增量加载，切版本不重复调用模型。

角色、场景、分支、任务与导出都执行服务端所有权检查；不要仅靠前端隐藏入口。用户内容默认私有，不自动公开、分享或用于全局角色记忆。提交给模型的内容限于当前任务所需信息；不在分析事件中记录原始正文、隐藏设定或私人聊天。具体模型供应商和保留策略在接入时按项目实际配置披露。

读屏可读出角色名、动作、按钮状态；装饰星点不进入可访问树。错误有文本说明。开启系统减少动态效果时停止流式逐字动画，可按块显示。200% 字号下主要流程可完成，所有内容可滚动访问。

## 20. 埋点与验证指标

事件：scene_create_started、cast_completed、setup_submitted、first_segment_completed、continue_clicked、intervention_applied、role_takeover_started、branch_created、version_switched、scene_result_saved、next_scene_created、export_completed、generation_failed。

只记录标识、操作类型、耗时、成功状态与长度区间；不上传原始创作文本到通用分析系统。指标按去重用户或场景定义，避免把反复点击当成功。

重点观察：新建到首段完成转化、完成首段到首次介入比例、生成失败率、保存本场结果比例、接续下一场比例、七日返回创作比例。通过定向访谈核实“是否采用对白或转折”“是否觉得人物符合设定”。数值阈值先取真实内测基线，再设正式目标，不虚构行业基准。

## 21. 验收标准

| ID | 场景 | 通过条件 |
|---|---|---|
| AC01 | 最短开场 | 两位已有角色＋合法局面即可生成，不强制补全可选字段 |
| AC02 | 快速创建 | 无头像也可加入；退出重进仍有草稿；重复点击不创建重复角色 |
| AC03 | 视觉主题 | 深靛背景、香槟金主操作、人物卡片及衬线标题一致；舞台正文清晰无高亮星点干扰 |
| AC04 | 角色隔离 | 私人聊天不自动注入；排戏不改变原角色记忆 |
| AC05 | 知识差 | 使用车站示例，许的反应不能无依据确认林已知秘密；以多组固定局面人工评估 |
| AC06 | 暂停 | 完整块保留，残缺块不保存，迟到事件不追加，继续不重复已提交对白 |
| AC07 | 导演指令 | 下一片段体现指令；一次性指令结束后不强制永久延续 |
| AC08 | 事件 | 一次事件只发生一次，超时重试不重复插入 |
| AC09 | 接管 | AI 不代写被接管角色的新决定；输入失败后仍保留，交还不自动生成 |
| AC10 | 编辑 | 用户锁定文字在后续生成中保持；剧情改动新建版本，原后文仍可访问 |
| AC11 | 走向差异 | 两卡在行动／信息／关系至少一个维度有实质区别，选择前不写入记忆 |
| AC12 | 分支隔离 | 版本 B 揭露秘密后，版本 A 角色仍维持原知识状态 |
| AC13 | 保存 | 自动保存和本场结果分开；重进恢复正确版本、完整内容与保存状态 |
| AC14 | 连续场景 | 下一场仅继承明确引用结果；改上一场结果不会静默覆盖下一场 |
| AC15 | 导出 | 中文无乱码，角色归属正确，不含隐藏设定和内部指令 |
| AC16 | 权限 | 账户间无法通过 scene/version/job/export ID 读取对方内容 |
| AC17 | 移动端 | 320px 宽、软键盘、底部安全区及大字号下无核心按钮遮挡 |
| AC18 | 故障恢复 | 刷新、切后台、断流后不丢已提交文本，不重复生成，不错误显示已同步 |

质量验证使用固定的双人场景集覆盖：信息差、对立目标、克制和解、角色底线、关系不对称、作者改台词、分支秘密泄露和长场接续。生成质量需人工检查，不能仅以结构化输出通过代替叙事质量通过。

## 22. 开发顺序和发布门槛

第一阶段：适配现有角色及身份体系、搭建主题组件、完成创建和草稿存储。

第二阶段：舞台分段生成、任务状态、暂停与恢复、角色知识状态。

第三阶段：导演介入、事件、接管、局部重演与版本隔离。

第四阶段：回顾、确认结果、导出、下一场、移动端与异常验收。

以上阶段是实施顺序，不是删减 P0 范围的许可。可内部逐阶段演示；对用户发布时需完成整个闭环，尤其是版本隔离、自动保存和恢复。

开发开始前确认现有导航入口、角色 schema、账户和持久化接口以及模型服务能力。这些是仓库映射工作，不要求用户重新决定产品方向。若现有能力不足，先给出具体缺口与适配方案，不擅自将不可用功能展示为已实现。

## 23. 端到端验收示例

1. 用户进入创作，点击「排一场戏」，选林和许。
2. 输入车站重逢局面，目标为表面温柔但关系出现裂痕，开始排戏。
3. 首段呈现咖啡、寒暄和回避，许没有无依据知道林已发现秘密。
4. 用户接管林，输入“有些事情，你倒是记得。”，AI 仅演许和环境。
5. 交还角色，加入“列车广播响起”，随后继续；广播事件不重复。
6. 用户在片段 02 选择其他走向，尝试“许主动承认部分事实”，生成版本 2。
7. 切回版本 1，确认没有出现版本 2 的坦白和对应记忆。
8. 用户认可版本 2，结束本场并保存；导出文本与所选版本一致。
9. 接着排下一场，带入版本 2 的坦白事实；原始角色私人聊天保持原样。

本版成功的标准：用户能把两个自己的角色放进同一个局面，得到可读的演出，真实改变其发展，保留可比较的版本，并将选中的故事继续写下去。
