# 初始评估计划

## 原则

先检查重建是否忠实于输入，再研究是否能支持角色表现。两者分别报告。所有阈值在试标注后制定；当前不预设商业级准确率。

| 层次 | 检查对象 | 初始指标／记录 | 人工检查方式 |
| --- | --- | --- | --- |
| 来源与归属 | 文本位置、人物、说话者、版本 | 定位有效率与归属错误数 | 回到原文逐项核对 |
| 主张 | 是否有充分支持、是否编造 | 支持主张数／全部输出主张数；另记矛盾与无法判定 | 判断支持关系，不以“有引用”算正确 |
| 覆盖 | 重要信息遗漏 | 人工重要主张的覆盖比例 | 先标重要程度与信息粒度 |
| 冲突 | 来源之间的矛盾和变化 | 冲突识别的精确率／召回率；类型错误 | 区分版本、时间和真实矛盾 |
| 人格解释 | 行为能否支持特质概括 | 推断合理性、替代解释、信息不足时的保留判断 | 有证据的分歧也保留，不强造唯一标签 |
| 下游表现 | 未见情境和多轮回应 | 情境行为符合度、知识边界错误、设定矛盾 | 匿名角色，避免只靠角色名字 |
| 用户审核 | 找错与纠正是否方便 | 审核耗时、修正数、修改可追溯性 | 后续用户任务；现在先内部演练 |

## 最小比较实验草案

基线 A：直接把同一组文本交给模型生成人物档案。

候选 B：分来源提取原子主张与原文，再整合人格解释。

控制相同材料、目标字段、基础模型和输出长度范围；提示词与调用预算记录在案。若 B 使用更多调用，报告成本差异，不能把提升全部归因于表示方式。后续增加相同预算对照。

试验角色与开发角色隔离。先用原创材料检查任务定义，再扩充到更多独立样例。标注人看不到系统名称，输出顺序随机。记录分歧和裁决理由；单人标注时明确局限，不报告虚假的标注者一致性。

每次实验至少记录：输入版本、Schema、提示词、模型标识、生成参数、代码提交、时间、调用次数、成本（能获得时）、输出、人工判断与错误案例。未取得的字段标为未知。
